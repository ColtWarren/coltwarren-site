Cloudflare OS

I am learning Cloudflare's application platform by operating my own Cloudflare OS deployment, building experiments, debugging real failures, and documenting the engineering process as I go.

Cloudflare OS is a Cloudflare project. This page documents my personal deployment, experiments, debugging work, and engineering work around the project. It is not presented as my original product.

Personal deployment live

Overview

My goal is to understand how Cloudflare intended OS capabilities to be assembled rather than treating the project as a black box. I am studying the relationships between Workers, Durable Objects, Cloudflare Access, AI Gateway, Workers AI, Gatekeepers, Blueprints, KV, R2, RPC, and the application layer that connects them.

Production Deployment

A private Cloudflare OS instance protected by Cloudflare Access and deployed across multiple Cloudflare Workers.

Hands-On Experiments

Small exercises designed to understand persistence, Blueprint portability, RPC behavior, Gatekeepers, scheduling, and Cloudflare storage primitives.

Build in Public

Failures, fixes, architecture decisions, and lessons are documented so the process is visible rather than only the finished result.

Architecture

The personal deployment keeps the public entry point narrow while internal capabilities communicate through Cloudflare's service and RPC model.

Resolved · Issue #1

Blueprint Upload Over Cloudflare Access

Diagnosed a production Blueprint upload failure caused by a raw ReadableStream crossing a promise-pipelined Cap'n Web RPC capability. Implemented and tested a minimal fix, deployed it, and verified the complete Blueprint portability path through Durable Object persistence.
